## [Anthropic's Jacobian Lens Reveals Hidden LLM Processing](https://www.technologyreview.com/2026/07/09/1140293/anthropic-found-a-hidden-space-where-claude-puzzles-over-concepts/) ⭐️ 9.0/10

Anthropic has developed a technique called the Jacobian lens that allows researchers to read out the internal activations of large language models, revealing a hidden conceptual processing space where Claude puzzles over concepts before producing output. This breakthrough provides unprecedented transparency into LLM reasoning, potentially enabling better debugging, safety analysis, and understanding of how models handle complex tasks like code error detection or prompt injection. The Jacobian lens linearly transports residual-stream vectors at any layer and position into the final-layer basis, then decodes them with the model's own unembedding to produce a ranked list of vocabulary tokens, revealing intermediate reasoning steps often absent from chain-of-thought and final output.

**Background**: Large language models like Claude process text through multiple transformer layers, each producing hidden representations that are difficult to interpret. Traditional interpretability methods often rely on probing or attention analysis, but the Jacobian lens offers a direct way to 'read' what the model is disposed to say at each internal step, providing a window into its latent conceptual space.

## [Running GLM 5.2 on a 32GB RAM Laptop via Colibrì](https://github.com/JustVugg/colibri) ⭐️ 7.0/10

A developer created Colibrì, a lightweight inference engine that runs the 744B-parameter GLM 5.2 model on a 32GB RAM laptop using int4 quantization and on-demand expert loading from disk, achieving 0.1 tok/s. This demonstrates that large MoE models like GLM 5.2 can be run on consumer hardware without a GPU, making advanced LLM capabilities more accessible and enabling local inference for privacy-sensitive or offline use cases. The model uses a Mixture-of-Experts architecture with 744B total parameters but only ~40B active per token; Colibrì keeps the dense part (~17B params) in RAM at int4 (~9.9 GB) and streams the 21,504 routed experts from disk (~370 GB) with an LRU cache. The engine is a single C file with no BLAS, Python, or GPU dependency.

**Background**: GLM 5.2 is a large language model developed by Zhipu AI, using a Mixture-of-Experts (MoE) design where only a subset of parameters are activated per token, reducing computation. Running such models locally typically requires high-end GPUs, but techniques like quantization (reducing precision) and offloading weights to disk can enable inference on limited hardware.

## [No Leap Second at End of December 2026](https://datacenter.iers.org/data/latestVersion/bulletinC.txt) ⭐️ 7.0/10

The International Earth Rotation and Reference Systems Service (IERS) announced that no leap second will be added to Coordinated Universal Time (UTC) at the end of December 2026. This decision provides temporary relief for digital systems that struggle with leap second handling, but the ongoing unpredictability of Earth's rotation means future adjustments remain necessary, impacting time-sensitive applications like financial trading and network synchronization. Since 1972, 27 positive leap seconds have been added to UTC, with the last one occurring on December 31, 2016. The IERS typically announces leap seconds about six months in advance, and the current UTC-TAI offset remains at -37 seconds.

hackernews · ChrisArchitect · Jul 9, 14:16 · [Discussion](https://news.ycombinator.com/item?id=48846281)

**Background**: A leap second is a one-second adjustment to UTC to keep it within 0.9 seconds of mean solar time (UT1), which varies due to irregularities in Earth's rotation. The IERS monitors Earth's rotation and decides when to insert or remove a leap second. This adjustment is necessary because atomic time (TAI) runs uniformly, while Earth's rotation gradually slows down unpredictably.
