GitHub has launched stacked pull requests in public preview, allowing developers to create and manage dependent PRs as a stack. This feature is one of the largest changes to GitHub in years, covering services from Actions to the web UI. Stacked PRs enable developers to break large changes into smaller, reviewable chunks, improving code review efficiency and reducing merge conflicts. This workflow, previously only available via third-party tools, is now natively supported on the world's largest code hosting platform. The feature is in public preview and has known issues, such as merging an entire stack being broken in many cases, and squash-and-merge requiring re-approval for each PR in the stack. **Background**: Stacked pull requests are a workflow where multiple PRs are built on top of each other, each depending on the previous one. Previously, GitHub did not natively support this workflow, forcing teams to use manual branch hierarchies or third-party tools.
