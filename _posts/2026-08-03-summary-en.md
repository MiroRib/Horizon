## [Rust Project Goals Propose !Move Types and Guaranteed Destructors](https://github.com/rust-lang/rust-project-goals/blob/main/src/2026/move-trait.md) ⭐️ 8.0/10

The Rust project goals for 2026 propose adding immobile types (!Move) and guaranteed destructors (!Forge), which could eventually deprecate the Pin type and enable safe scoped spawn. This is a project goal, not an accepted language change, meaning the design may evolve or be abandoned. This proposal addresses a long-standing gap in Rust for immovable types, which have been a pain point since around 2016 and led to the Pin hack. If implemented, it could simplify async code and improve memory safety by making destructors guaranteed to run, benefiting systems programmers and the broader Rust ecosystem. The proposal introduces !Move as a type-level property, contrasting with the current place-based Pin, and !Forge as a guarantee that a type cannot be forgotten, ensuring its destructor runs. It also mentions !Destruct (linear types) as a related concept, where values must be consumed by a function rather than implicitly dropped.

hackernews · paavohtl · Aug 3, 06:42 · [Discussion](https://news.ycombinator.com/item?id=49152023)

**Background**: In Rust, types have move semantics by default, meaning values can be relocated in memory. However, some types (like self-referential structs) cannot be safely moved, which led to the introduction of Pin to pin values to a fixed address. The proposed !Move trait would make immovability a property of the type itself, potentially simplifying the language and removing the need for Pin. The project goals document outlines these proposals as part of Rust's 2026 roadmap.

AirLLM, an open-source framework, now allows inference of 70B-parameter large language models on a single 4GB GPU by loading only one layer at a time. This reduces VRAM usage from roughly 140GB to under 4GB, though inference speed is extremely slow. This significantly lowers the hardware barrier for experimenting with large models, enabling hobbyists and researchers with modest GPUs to run models that previously required enterprise-grade hardware. It also sparks discussion on performance trade-offs and the future of model architecture optimization. The framework requires a minimum of 16GB RAM and works by loading each decoder layer (about 1.7GB for a 70B FP16 model) onto the GPU sequentially. Users still need to download the full model to disk, but RAM requirements are reduced, and it supports integration with HuggingFace.

**Background**: Large language models like 70B-parameter models typically require massive GPU memory (e.g., 140GB in FP16) for inference, which is beyond the reach of most consumer hardware. AirLLM uses layer-wise inference, a technique that loads only one model layer at a time, trading off speed for drastically reduced memory usage. This approach is part of a broader trend of optimizing LLM inference for low-resource environments.
