## [Deno 的 Celld 将 Durable Objects 带入自托管领域](https://github.com/denoland/celld) ⭐️ 8.0/10

Deno 发布了 Celld，这是一个自托管的分布式 Durable Objects 运行时，使用 SQLite 和兼容 S3 的存储，使开发者能够独立于任何云提供商运行 Durable Objects。 这意义重大，因为 Durable Objects 此前是 Cloudflare Workers 的专有功能，现在以开源、自托管的形式提供，让开发者对基础设施有更多灵活性和控制权。这可能加速 Durable Objects 模式在整个生态系统中的采用。 Celld 的设计使得每个对象都是独立的 SQLite 数据库，通过名称寻址，并复制到你拥有的兼容 S3 的存储桶中。这种设计强调强大和简单，但目前需要配置兼容 S3 的存储后端，这可能增加初始设置的复杂性。

hackernews · calvinfo · Aug 5, 16:50 · [社区讨论](https://news.ycombinator.com/item?id=49185430)

**背景**: Durable Objects 是由 Cloudflare 推广的概念，提供全局唯一、单线程的计算实例，并具有持久化存储。它们通常用于边缘计算中管理有状态的工作负载。Celld 旨在将这种模式带入自托管环境，利用 SQLite 进行本地存储，并使用兼容 S3 的存储进行复制和持久性。

## [Webhook 可靠性问题与 SCROLL 协议提案](https://weli.dev/blog/the-valley-of-webhooks/) ⭐️ 8.0/10

一篇博客文章批判性地分析了 webhook 在状态同步方面的局限性，并提出了一种名为 SCROLL（基于行日志的同步变更复制）的新协议，该协议以 IETF 风格草案的形式呈现。该文章获得了社区的高度关注，获得了 136 个点赞和 61 条评论。 这一讨论凸显了 API 设计中对可靠状态同步的需求日益增长，因为 webhook 常常无法保证消息的投递和顺序。所提出的 SCROLL 协议与实际的 IETF 草案（Braid-HTTP Subscriptions）相似，可能影响未来的标准制定，并改进系统间数据同步的方式。 SCROLL 协议使用带有 'Prefer: stream' 头的 GET 请求来建立订阅，这与 Braid-HTTP Subscriptions 草案类似。社区成员指出了潜在的低效问题，例如低频事件下的持久连接，并提出了诸如游标分页或混合方法等替代方案。

hackernews · weli · Aug 5, 15:22 · [社区讨论](https://news.ycombinator.com/item?id=49184216)

**背景**: Webhook 是服务器通知客户端变更的常见方式，但它们存在投递保证、顺序和去重等问题。系统间的状态同步通常需要可靠的事件投递，而 webhook 可能无法提供。SCROLL 协议旨在通过提出一种标准化方法来解决这些问题，其灵感来源于 IETF 草案，如 Braid-HTTP Subscriptions。
