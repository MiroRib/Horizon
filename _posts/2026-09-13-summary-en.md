The project addresses a major pain point for AMD users who want to run CUDA-only AI and HPC workloads without buying Nvidia hardware. Projects like ZLUDA have previously attempted to run unmodified CUDA applications on non-Nvidia GPUs by acting as a drop-in replacement. This new project applies a similar idea specifically to Windows and AMD GPUs.

## [Tesla's Misconfigured NTP Setup Floods Blogger's Server](https://dreamstation.systems/personal/tesla.html) ⭐️ 7.0/10

The post sparked a discussion on Hacker News about vendor NTP best practices and security risks. This incident highlights how a single vendor misconfiguration can create operational and security problems for unrelated third parties, and it raises concerns about compliance with NTP pool vendor guidelines. The misconfiguration involves hardcoding pool.ntp.org zone names as the default and CNAMEing pool-ntp.tesla.com to a domain Tesla does not control, which could allow someone to request a certificate for pool-ntp.tesla.com. The NTP pool's vendor guidelines explicitly state that the default pool.ntp.org zone names must not be used as the default configuration in applications or appliances.

## [Why x86's undefined instruction is called UD2](https://devblogs.microsoft.com/oldnewthing/20260910-00/?p=112689) ⭐️ 6.0/10

Raymond Chen's Old New Thing blog post explains that x86's recommended undefined instruction is named UD2 because the 0F FF opcode was retroactively named UD0 and the 0F B9 opcode was retroactively named UD1, leaving UD2 (0F 0B) as the architecturally guaranteed undefined instruction. This matters because UD2 is widely emitted by compilers (e.g., Go's runtime.panicindex) and is used in crash analysis and API detouring, so understanding its naming and architectural guarantees helps low-level developers interpret disassembly and SIGILL faults correctly. UD2 is architecturally guaranteed to raise an invalid opcode exception, while UD0 and UD1 are not as consistently defined; some processors decode UD0 without a ModR/M byte, and UD1 was only officially reserved as an invalid opcode from Pentium onwards.

hackernews · ibobev · Sep 13, 12:30 · [Discussion](https://news.ycombinator.com/item?id=49683262)

**Background**: x86 processors use opcodes to encode instructions, and some opcode values are reserved as undefined or invalid so that executing them raises an exception. Over time, Intel retroactively assigned the mnemonics UD0, UD1, and UD2 to three such opcodes: 0F FF, 0F B9, and 0F 0B. UD2 became the recommended one because its behavior is consistent and architecturally guaranteed across processors.
